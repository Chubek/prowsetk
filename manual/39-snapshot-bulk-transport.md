# Chapter 39: Snapshot Bulk Transport

[Manual index](README.md)

## Why bodies moved off the socket

Chapters 31–34 describe a conversation whose page HTML travelled inside the
newline-delimited JSON control message. That encoding is convenient and it is
bounded, but it costs twice: JSON escaping inflates every byte, and a real
application page does not fit. A 4 MiB capture limit was reached by markup
rather than by page complexity, and a page with heavy quoting or embedded source
could exhaust the encoded-message budget well before the intended HTML bound.

The bridge now keeps JSON for control and moves bodies through private named
FIFOs. Control messages stay small and human-inspectable, bodies travel verbatim
as raw UTF-8, and the HTML bound is expressed once, in bytes, at 16 MiB —
matching Flatworm's own input bound rather than a transport artifact.

This is an internal transport change. The operations in Chapter 31 are
unchanged, the Lua and Python companions still publish and receive the same
snapshot tables, and a descriptor without the bulk field keeps the previous
inline behavior.

## Frame layout

A FIFO body is one frame with no terminator beyond end of stream:

```text
offset  size  content
     0     7  ASCII magic  "QHTML1\n"
     7     8  unsigned 64-bit big-endian byte count of the body
    15     N  exactly N bytes of raw UTF-8 page HTML
```

The count is verified against the announced `html_bytes` and against the bytes
actually read. A reader stops when it has the header plus exactly the announced
length; one byte more is a protocol violation, not a short read that should be
retried. A body that ends early, or never arrives, is a truncated frame.

Every FIFO is created by the party that will write it, inside the broker's
owner-only runtime directory, with mode `0600` and a generated name:

```text
bulk-<32 lowercase hex characters>.fifo
```

The name is a token, not a path. Both peers validate the basename shape and
resolve it only as a child of the descriptor's directory, so a peer cannot
redirect a transfer elsewhere or reuse a name it did not receive.

## The two hops

Bodies cross two local hops, each with the same framing:

```text
Qutebrowser tab
  └─ ptk-qute-scrape / ptk-qute-marionette ──┐
                                              │  hop 1: sender → broker
                                  Unix socket (control JSON only)
                                            │
                                            ▼
                                        broker (retains latest capture)
                                            │
                                  Unix socket (control JSON only)
                                            │  hop 2: broker → Lua client
                                            ▼
                       lquteipc read_fifo  →  qutebrowser_bridge.lua
```

Hop 1 lets a userscript publish markup larger than any encoded message without
buffering it through the socket. Hop 2 returns the retained capture, or a fresh
capture produced by a Chapter 33 action, to a Lua client.

Because both hops are local and independent, one can fail without corrupting
the other: a rejected control message means no FIFO is consumed, and an
incomplete body means the frame fails validation and the capture is discarded
rather than partially loaded.

## Control messages and the descriptor

The descriptor gains one optional field:

```json
{"version":1,"socket":"...","token":"...","origin":"...","bulk":"fifo-v1"}
```

`bulk` is the negotiated transport for that conversation. Its absence means the
older inline path. Any other value is rejected.

Publishing carries metadata instead of markup:

```json
{"version":1,"token":"...","op":"publish",
 "snapshot":{"url":"...","tab":1,"purpose":"page",
             "html_fifo":"bulk-….fifo","html_bytes":6291456}}
```

`url`, `tab`, and `purpose` keep the Chapter 31 validation and the approved
origin check; `html_fifo` and `html_bytes` replace the inline `html` member.
The broker reconstructs a normal snapshot table before applying the ordinary
publish rules, so action captures still require a matching pending action ID and
tab index.

Receiving is symmetric. A `snapshot` or `act` reply for a bulk conversation adds
`"transport":"fifo"` to the request; a reply snapshot then contains
`html_fifo` and `html_bytes` instead of `html`. The reader substitutes the body
before the snapshot reaches Lua, so `qute.load_snapshot` and the Chapter 32
companion API are unaware of the transport.

## Validation and safety

Both implementations enforce the same contract, and every check happens before
the bytes reach a parser:

| Check | Rule |
|---|---|
| Directory | Owner-only (`0700`), owned by the caller, not a symlink |
| Name | Exactly `bulk-<32 hex>.fifo`, generated by the peer |
| File kind | FIFO, never a regular file, device, or symlink |
| Ownership and mode | Owned by the caller, no group or other permissions |
| Framing | Magic prefix, announced length equals actual length |
| Termination | Exactly the announced bytes, then EOF |
| Encoding | Valid UTF-8, no NUL bytes |
| Size | 0 to 16 MiB, announced in advance |

Openings use `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`, so a symlink planted in the
runtime directory is refused rather than followed. Failures are reported with a
fixed, value-free error; the body never appears in a message. A rejected frame
closes the descriptor, which a concurrent writer may observe as a broken pipe —
that is expected and not a bridge fault.

The transport adds no trust relationship. As in Chapter 31, the peer-UID check
on Linux and the private descriptor already define the trust boundary; FIFOs
make bulk transfer efficient without widening it.

## Backpressure, deadlines, and cleanup

Both peers use nonblocking I/O with poll deadlines, because a 16 MiB body does
not fit in a pipe buffer and a naive write would either block or truncate.

A writer opens the FIFO with a bounded retry, because opening for write on a
FIFO with no reader fails until a reader arrives. It then writes in chunks,
waiting for writability before each one. A reader polls for readability and
reads only as much as remains, so it never overruns the announced length.

Both directions carry a 10-second per-hop deadline, independent of the 30-second
control wait of Chapters 31 and 33. Timeouts fail the transfer with the same
generic error as any other protocol violation.

A reader that sees EOF before any data does not immediately conclude the writer
failed: opening and writing are separate steps, so a brief retry absorbs that
window and a missing peer is still rejected once the deadline passes.

Cleanup is owned by the party that created the FIFO. A normal exit or a handled
failure unlinks it; an abrupt process kill can leave an empty FIFO node behind,
which the owner may remove once the dead process is gone. Leftover nodes are
harmless: the next conversation uses a freshly generated name.

## Two implementations, one contract

The Python and native sides deliberately mirror each other so the protocol is
reviewable in one place and testable on both sides.

| Side | Files | Role |
|---|---|---|
| Python | `protocol.py`, `bulk.py`, `broker.py`, `userscript.py` | Descriptor, control framing, FIFO creation and streaming, broker assembly and delivery |
| Native Lua | `ipc.cpp`, `fifo.cpp` | `lquteipc.read_fifo` for the Lua client hop, sharing the socket and private-file helpers |

`lquteipc` gains one entry point beside `exchange`, `read_private`, and
`write_private`:

```lua
local body = ipc.read_fifo(directory .. '/bulk-….fifo', byte_count)
if not body then return end  -- value-free failure
```

It validates the same directory, name, kind, ownership, framing, and length
rules as the Python reader, then returns the exact bytes. The Lua client
additionally verifies the returned length, UTF-8 validity, and absence of NUL
bytes before it treats the body as a snapshot. Failures surface as a generic
bridge error rather than the underlying reason.

Keeping this logic out of Lua means the assistant connection still never reaches
a shell, never opens a page socket, and keeps its private file handling in one
small audited module.

## Bounds

| Bound | Value |
|---|---|
| FIFO body (both hops) | 16 MiB |
| Encoded control message, or legacy inline body | 8 MiB |
| Bulk transfer deadline | 10 seconds per hop |
| Snapshot/action control wait | 30 seconds |
| JSON nesting | 32 levels |

The HTML bound and Flatworm's parser bounds apply independently. A capture
within the transport bound can still be rejected by the parser for node count
or nesting depth; the two limits are not interchangeable, and passing one says
nothing about the other.

The legacy inline path remains supported for descriptors without `bulk`. It is
bounded by the encoded-message limit, not by the HTML bound, because escaping
still applies to it.

## Verification

```sh
ctest --preset default -R 'qutebrowser|Qutebrowser'
ctest --preset asan -R 'qutebrowser|Qutebrowser'
```

Coverage is hermetic and needs no browser: unit tests exercise framing,
truncation, overrun, wrong lengths, mismatched headers, unsafe names, permission
changes, symlinks, and stalled peers on the Python side, plus the native reader
against a live FIFO. Integration tests push multi-megabyte, escape-heavy pages
through both real hops and assert byte-exact delivery, that a mismatched frame is
refused without echoing peer bytes, that no FIFO node survives a normal exit, and
that the failure path preserves the caller.
